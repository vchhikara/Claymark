# Claymark Android → Linux/Windows Desktop port checklist (2026-09-18)

Exhaustive feature/design inventory of `android/` (the finished
Android app), for the session working on the Linux/Windows Tauri desktop
installables (see `handoff-installables.md` for that session's build-system
context — this file is the *feature parity* checklist, that one is the
*build tooling* checklist; read both).

**How to use this**: the desktop app is the `claymark` web app wrapped by
Tauri (`desktop/`, source in `src/`) — a different codebase from
`android/`, already presumably ahead of Android on some things (full
Shiki highlighting, streaming markdown, richer math). This checklist is NOT
"build all of this from scratch" — it's "here's everything Android has;
check each item against what the desktop/web app already does, and close
real gaps." Several items below are explicitly marked **Android-only
simplification — do not downgrade desktop to match**; don't literal-port
those backwards.

Generated by reading the entirety of
`android/app/src/main/java/com/claymark/nativeapp/` (all ~30 Kotlin
files across `documents/`, `markdown/`, `session/`, `theme/`, `ui/`,
`widget/`), `AndroidManifest.xml`, and the project's own docs
(`README.md`, `PROCESS.md`, `BUILD-AUDIT.md`, `HANDOFF-2.md`,
`archive/print-support/README.md`). All numeric values (hex colors, dp/sp
sizes, alpha values) below are taken verbatim from source — nothing here
is approximated or invented.

## 1. Screens / Routes

- [ ] **Welcome screen** — cold-launch-only state (never shown for share/open-with launches). Hamburger top-left, centered wordmark (32sp), tagline "A Markdown renderer built for streamed, untrusted LLM output." (max width 280dp, centered, muted), primary "Open file" button (70% width), secondary text-only "View sample" link. "View sample" loads the bundled sample doc.
- [ ] **Reader screen** — main document view (chrome detailed in §4).
- [ ] **Settings screen** — reached via drawer icon row.
- [ ] **Help screen** — static content rendered through the app's own Markdown pipeline (dogfooding).
- [ ] **About screen** — bundled-library attribution (KaTeX MIT, Mermaid MIT, Source Serif 4/Inter/JetBrains Mono OFL 1.1, commonmark-java BSD-2), rendered through the Markdown pipeline.
- [ ] **Privacy screen** — "collects nothing" statement: no analytics, no crash reporting, zero runtime network requests; states what's stored locally.
- [ ] All four sub-screens share one shell pattern: back-arrow + title header, 1dp hairline divider, scrolling measure-capped body.
- [ ] **Print is explicitly NOT present** — archived, not a requirement (see §8).

## 2. Core Markdown Rendering Features

### Parsing
- [ ] CommonMark + GFM (tables, strikethrough, task lists, autolink).
- [ ] Display math (`$$…$$`) preprocessed into a synthetic fenced block before parsing (fenced/single-line, skips real code fences).
- [ ] Inline math (`$…$`) detected via regex at render time.
- [ ] Raw HTML (block + inline) parsed but rendered as literal escaped text — never executed, no override.
- [ ] Word count from parsed AST (Text + Code nodes only) — fence markers/`#`/link syntax never inflate it.

### Block rendering
- [ ] Headings h1–h6, always body-serif weight 600 — never a separate display face.
- [ ] Heading anchor/slug generation: lowercase, strip non-alnum, collapse spaces/underscores to `-`, trim `-` — must match exactly for TOC deep-linking.
- [ ] Single-image-only paragraph unwraps into a standalone "figure" block.
- [ ] Pure-plain-text paragraph containing inline math routes whole to KaTeX (mixed bold/link/code + math in one paragraph is an Android-only gap, see §8).
- [ ] Bullet lists: 3-level marker rotation (disc → circle → square).
- [ ] Ordered lists: 3-level rotation (decimal → lower-alpha → lower-roman), respects custom start number.
- [ ] Nested lists (recursive).
- [ ] Task list checkboxes: **display-only**, not interactive.
- [ ] Blockquotes: left border rule (`quoteRule` token, width = Space.s1), text color `textSecondary`, nested blocks supported.
- [ ] Thematic break (`---`): renders as blank vertical space (Space.s6 height) — **no visible line**.
- [ ] Fenced code blocks with language info-string.
- [ ] Fence meta line-highlight ranges (`` ```js {2,4-6} ``) → tinted background on matching lines.
- [ ] Indented (4-space) code blocks: no chrome (no header/badge/copy button) — distinct from fenced.
- [ ] Math fences render via KaTeX, no copy button/language chrome.
- [ ] Mermaid fences render via Mermaid; invalid syntax **falls back to raw-source code block**, never crashes.
- [ ] Standalone image: full-width, tappable → lightbox; alt-text fallback box if undecoded; optional `title` → centered caption below.
- [ ] Inline (non-standalone) images degrade to muted alt text.
- [ ] Raw HTML block → literal text.
- [ ] Links: only absolute http(s)/mailto navigable, opens via system/external handler, never in-app navigation.
- [ ] Every href/src passes through URL policy — rejected ones render inert text, never drop the surrounding element.

### Inline rendering
- [ ] Emphasis → italic; strong → weight 700 bold (explicitly distinct from heading's 600); strikethrough → line-through.
- [ ] Inline code, two visual treatments by heuristic:
  - [ ] "Reference" (paths with `/`, or bare filenames not ending in a unit suffix like em/rem/px/%/deg/vh/vw/ms/fr) → plain mono text, no pill, `codeRef` color.
  - [ ] "Value" (everything else) → rounded padded pill, `pillBg` background, mono text, `codeInline` color.
- [ ] Inline code size = body × 0.85.
- [ ] Links underlined, `link` token color, destination validated.
- [ ] Inline images → muted alt text; raw inline HTML → literal text.
- [ ] Soft break → single space; hard break → newline.

### Tables
- [ ] Row-separator borders only (not full grid) — shadcn/ui Table pattern.
- [ ] Column widths from actual measured text (real font/weight), per-column cap 40dp–320dp + `Space.s3 * 2` padding.
- [ ] **Horizontal scroll inside the table's own container only** — page itself never scrolls sideways.
- [ ] Table wrapped in a `clayPot` treatment (raised outer lip + sunken inner well), thin insets (0.75dp h/v).
- [ ] Interior padding (`Space.s2`) so edge cells never sit flush against the rim.
- [ ] Header row: SemiBold, code-sized type (15sp). Body cells: Normal weight, same size.
- [ ] Default alignment **left** unless source explicitly marks `:---:`/`---:`/`:---`.
- [ ] Row divider (between rows, not after last): two stacked 1dp lines — white-alpha "rim" then black-alpha "sink" (rimAlpha 0.85 light/0.16 dark, sinkAlpha 0.08 light/0.45 dark) — matches the outer clayPot rim treatment.
- [ ] No full-width stretch — table takes only the width its columns need.
- [ ] Text never overflows/breaks cell layout (measured widths prevent it).

### Code blocks
- [ ] Header (language badge + copy button) sits in normal flow above the code — never floats/overlaps on narrow viewports.
- [ ] Long lines **wrap** inside the block — never forces sideways page scroll.
- [ ] "Pressed"/engraved visual treatment (flattened shadow, no rim-light, elevation 4dp).
- [ ] Language badge as a pill when language present.
- [ ] Copy button copies exact fence source; "Copy" → "Copied" label swap for 2s; flat styling (no shadow/border, already inside an engraved container).
- [ ] Highlighted-line ranges get a tinted row background (`surfaceRaised`).
- [ ] Code text: mono, 12sp, 1.5× line-height.

### Syntax highlighting — **Android-only subset, see §8 before touching desktop's**
- [ ] (Reference only) Android's fixed 34-language hand-rolled lexical highlighter with GithubLight/GithubDarkDimmed palettes — desktop should keep its existing full Shiki-based highlighting, not regress to this.

### Math and diagrams
- [ ] KaTeX renders math (inline-paragraph + display) in a sandboxed webview, local assets only.
- [ ] Mermaid renders diagrams same way; theme = `"dark"`/`"default"` matching app theme.
- [ ] Pinned reference versions: **KaTeX 0.16.47**, **Mermaid 10.9.8** — check desktop is on compatible/intentional versions, don't silently drift.
- [ ] Mermaid render failure → falls back to raw source as a code block, never blank/broken.

### URL/link policy
- [ ] Allow-listed schemes only: `http`, `https`, `mailto`.
- [ ] `data:image/{png,jpeg,gif,webp}` allowed for images only, never links.
- [ ] Percent-escape/control-char probe on the scheme portion to catch obfuscated payloads (e.g. `java%09script:`).
- [ ] Relative URLs treated as safe (local context).
- [ ] Verify desktop's existing URL policy matches this allow-list exactly (or intentionally differs, e.g. remote images — see §8).

## 3. Document Management Features

- [ ] Open file → native file picker, persistable handle.
- [ ] Create/Save-as → native save dialog, persistable writable handle.
- [ ] Display-name resolution with fallback to last-path-segment parse.
- [ ] Writability re-checked before every save (not just trusted from open time).
- [ ] "Open with"/externally-launched documents open **read-only** — Save unavailable, only Save-as.
- [ ] Save = truncate-then-write (no trailing old bytes on a shorter document).
- [ ] Save-as suggested filename = current doc name (or "untitled.md"), `.md` appended if missing `.md`/`.markdown`.
- [ ] **Crash-recovery draft buffer**: always-on regardless of autosave setting, debounced 700ms, keyed by document id.
- [ ] Draft auto-clears once text matches last-saved state.
- [ ] On open, if stored draft differs from disk content, draft is surfaced (recovered) with a "recovered unsaved changes" banner + Discard action.
- [ ] Draft force-flushed (no debounce) on backgrounding — desktop: flush on window blur/close/suspend, synchronously before quit.
- [ ] Separate debounced (1200ms) autosave-to-actual-file, gated on: autosave setting ON *and* document writable in-place — never silently triggers a save-as file-picker mid-keystroke.
- [ ] Autosave re-validates on wake before writing (avoid racing a manual save).
- [ ] Successful autosave → transient "Saved" toast.
- [ ] Recent files: locally persisted MRU, capped at **5**, most-recent first, reopening moves to front (no dupes).
- [ ] Only documents with a **persisted** grant are recorded (transient "Open with" grants and synthetic share-text docs excluded — they'd fail to reopen after restart).
- [ ] Stale MRU entries auto-removed if reopening fails.
- [ ] Session state machine: NO_DOCUMENT / VIEWING / EDITING / SAVING / SAVE_FAILED, with save statuses CLEAN/DIRTY/SAVING/SAVED/FAILED — no representable invalid combination.
- [ ] Unsaved-changes ("abandon") dialog triggers uniformly for: Back while editing-dirty, Open-file/Open-recent while editing-dirty. Options: Save / Discard / Cancel.
- [ ] "Back to preview" from a **failed** save also routes through the abandon prompt (not silent discard).
- [ ] Table of contents/outline derived from the same parsed-heading list the reader renders (`collectHeadings`) — one source of truth, not a second parallel walker.
- [ ] Search: plain-text character-offset matching, same implementation for view and edit modes.
- [ ] View-mode search "next/prev" jumps to nearest containing heading (reuses outline/scroll) — not full inline-match-highlighting (deliberate simplification).
- [ ] Edit-mode Replace-one/Replace-all operate on the exact plain source string.
- [ ] Word count + reading time (`words / 200`, round up, min 1 minute) shown in status bar.

## 4. UI Chrome and Navigation

### Drawer / sidebar
- [ ] Width capped at **240dp** in both modes.
- [ ] **Responsive breakpoint at ~600dp window width** — this is the one that maps directly onto desktop window resizing:
  - [ ] Below 600dp: modal slide-over drawer (scrim, hamburger-toggled, swipe-gesture, predictive-back-aware).
  - [ ] At/above 600dp: **permanent two-pane layout** — fixed 240dp left column + 1dp divider + content pane, hamburger toggles visibility (no slide gesture).
- [ ] Drawer content, top to bottom: logo mark (26dp) + wordmark lockup; "Recent" section (only if non-empty) in a `clayPot` box with 0.75dp insets, `.md` suffix stripped from filenames, single-line ellipsis; flexible spacer; row of 4 **icon-only** nav buttons (Settings/Help/About/Privacy, evenly spaced, no text labels); version string in mono font at bottom.
- [ ] Active sub-screen's drawer icon shows accent-brand tint + 16%-alpha tinted background.

### Reader header/toolbar
- [ ] Sticky header, status-bar-inset aware.
- [ ] Header content max-width = same `Measure` (864dp) as body column, centered.
- [ ] Header content never wraps/overflows: filename gets flexible+ellipsis, action buttons never shrink.
- [ ] Not-editing layout: hamburger, wordmark (only when no doc open, muted), "Open file" button, (doc open) "Edit" button + search icon, (headings exist) outline/TOC icon, theme toggle icon.
- [ ] Editing layout: "Back" text button, filename + save-status subtitle (right-aligned, ellipsis), optional "Save as…" button (only when primary button says something *different*, e.g. primary is a true in-place Save), primary persist button (label driven by action: Save / Save as / Download copy).
- [ ] 1dp hairline divider below header.
- [ ] All header controls pinned to fixed **36dp height** — avoids visible mismatch between text vs. icon control sizing.

### Formatting toolbar (edit mode)
- [ ] Bold (B) / Italic (I) / Code (`</>`) / Link ("Link" text) / List ("List" text) — text-glyph buttons, not icon-font.
- [ ] Bold wraps `**`; Italic wraps `_`; Code wraps `` ` ``; List inserts `- ` at line start; Link inserts `[text](url)` with "url" pre-selected for overtype.
- [ ] No-selection case still inserts markers with caret placed between them.

### Reading-progress rail
- [ ] Thin (3dp) vertical fill, left edge, proportional to scroll (0–1, min 0.0001 visible sliver at top).
- [ ] **No separate unfilled track** — sits directly over the existing divider line (avoids doubling apparent thickness).
- [ ] Hidden while editing.

### Search bar
- [ ] Query row always shown: inset text field ("Find in document"), match counter (`n/total` or `0/0`), prev/next arrows (disabled when no matches), close (X).
- [ ] Replace row shown only while editing: inset replace field ("Replace with"), "Replace" (one) + "All" buttons, both disabled when no matches.
- [ ] Fields use sunken (`clayInset`) styling, not raised.

### Table of contents dialog
- [ ] Modal (max 340×480dp), titled "Outline", scrollable list; h1/h2 SemiBold, deeper levels Normal; 12dp indent per level beyond 1; single-line ellipsis; tap → jump + dismiss.

### Theme picker dialog
- [ ] Modal (max 320dp): Auto/Light/Dark; selected shown accent-colored + SemiBold + checkmark; tap applies immediately and closes.

### Abandon-draft dialog
- [ ] "Save changes to {document}?" — Cancel/Discard/Save, compact right-aligned row.
- [ ] **Must be a true platform/OS-level modal window, not an in-layout overlay** — precedent bug: a runaway-width row could push a positioned overlay off-screen, making buttons untappable. Desktop: use a real native modal for this dialog specifically.
- [ ] Dismiss via outside-tap or Escape/Back → maps to Cancel.

### Image lightbox
- [ ] Tap image → full-screen 70%-black scrim, fit-scaled image, tap anywhere (incl. outside) or Escape/Back closes, restores prior scroll position.
- [ ] Undecodable image auto-closes itself as a side effect (not during composition/render).

### Toasts
- [ ] Small corner-anchored, non-blocking, auto-dismiss (2.2s) — Sonner-style, not a full-width Snackbar.
- [ ] Used for exactly one thing today: confirming a silent autosave completed.
- [ ] Slide-up + fade animation, bottom-center above safe area.

### Tooltips
- [ ] Dark/inverted popup bubble (bg = `textPrimary`, text = `surface` — inverts per theme), auto-dismiss 1.8s.
- [ ] Android trigger = long-press (no hover on touch) — **desktop should use standard hover-based tooltips instead**, not long-press.
- [ ] Applied to: theme toggle, back button, drawer menu button, scroll-to-top button, any icon-only button given a tooltip label.

### Status bar / footer
- [ ] "Notepad-style" bottom line, shown only when a document is open and not editing: filename (left, ellipsis, flexible) + "N words · M min read" (right) — both **mono** font, 1dp top divider.

### Scroll-to-top button
- [ ] Floating circular (36dp, fully round) raised button, bottom-right, appears after scrolling past 400px, up-arrow glyph, long-press/hover → "Scroll to top" tooltip.

### Notice/alert row
- [ ] Shared shape for: (1) "Recovered unsaved changes from a previous session" + Discard action; (2) "Couldn't save {file}. {error}" + Retry action, danger-colored 1dp border on the error variant.

### Theme toggle
- [ ] Header icon toggling Light/Dark explicitly (never reaches Auto from here — Auto is Settings-only).
- [ ] Custom hand-drawn monochrome sun/moon glyphs — explicitly not platform emoji (avoids full-color OS pictures clashing with the palette).

### Keyboard shortcuts — **directly desktop-relevant, verify these exist**
- [ ] **Ctrl+F** → open search bar.
- [ ] **Ctrl+S** → save (only while editing).
- [ ] **Ctrl+E** → toggle edit/preview (only if a document is open).
- [ ] Intercepted at the root, before any child (e.g. a focused text field) can consume the keystroke — desktop build must ensure these fire even while the editor has focus.

### Back/Escape handling
- [ ] While editing: Back/Escape routes through "Back to preview" (may trigger abandon dialog) rather than exiting.
- [ ] From a sub-screen: Back/Escape returns to the reader.

## 5. Settings Screen Features

- [ ] **Enable autosave** toggle, subtitle "Files will be automatically saved." Default **ON**.
- [ ] **Theme** row → opens Theme Picker (Auto/Light/Dark), subtitle shows current selection.
- [ ] **AMOLED Dark Theme** toggle, subtitle "Use a pure black background instead of the default." Default **OFF** (opt-in). Only meaningful in dark mode — desktop equivalent may not apply (no OLED-power-saving reason on desktop) but a pure-black theme option is still a legitimate design choice to consider.
- [ ] **Text size** stepper — discrete `+`/`−` icon buttons (not a slider), 4 steps: 0.875× / 1.0× (default) / 1.15× / 1.3×, subtitle shows step label (Small/Default/Large/Extra large).
- [ ] Text-size scale applies **only** to the reading surface (body/headings) — chrome/buttons/Settings text never scales with it.
- [ ] No analytics/telemetry/error-reporting toggle exists anywhere — zero runtime network requests by design; don't invent one.
- [ ] Settings persisted locally (equivalent of a local config store).

## 6. Theme / Design System — port this precisely, values are exact

### Color tokens

**Neutral ramp** (hue=60°, saturation=3.4%, HSL lightness per step):
n100=98% · n200=96% · n300=93% · n400=88% · n500=80% · n600=68% · n700=56% · n800=44% · n900=30% · n1000=15% · n1100=10% · n1200=7%

**Clay accent ramp** (hex, the one deviation from HSL-triplet convention):
- Clay.c400 = `#E29981`
- Clay.c500 = `#D97757`
- Clay.c600 = `#C8542D`
- Clay.c700 = `#BD4D28` — used specifically as the **light-theme link color** because c600 measured 4.23:1 and c500 2.99:1, both failing WCAG AA 4.5:1 against `--surface`. **Do not substitute c500/c600 for the light-theme link — verify desktop already uses c700 or an equivalently-contrast-checked value here.**

**Light theme**:
- [ ] surface = HSL(48°, 45%, 98%)
- [ ] surfaceRaised = n200
- [ ] surfaceCode = HSL(48°, 45%, 98%) — same as surface
- [ ] pillBg = HSL(0°, 0%, 94%)
- [ ] textPrimary = n1000 · textSecondary = n900 · textMuted = n800
- [ ] borderSubtle = n400 · borderDefault = n500
- [ ] link = Clay.c700
- [ ] quoteRule = `#0550AE` (reused from syntax highlighter's light "number" token)
- [ ] accentBrand = Clay.c700
- [ ] danger = HSL(0°, 70%, 50%)
- [ ] codeInline = `#A84545` · codeRef = `#3367D6`

**Dark theme**:
- [ ] surface = HSL(0°, 0%, 9.8%)
- [ ] surfaceRaised = n1100
- [ ] surfaceCode = HSL(0°, 0%, 18%)
- [ ] pillBg = HSL(0°, 0%, 18%)
- [ ] textPrimary = n200 · textSecondary = n400 · textMuted = n600
- [ ] borderSubtle = n800 · borderDefault = n700
- [ ] link = Clay.c400
- [ ] quoteRule = `#6CB6FF` (dark "number" token)
- [ ] accentBrand = Clay.c500
- [ ] danger = HSL(0°, 70%, 50%)

**AMOLED theme**:

### Claymorphism system — **scope is chrome only, not the reading surface**

- [ ] **The reading surface (prose/headings/lists/quotes/tables) uses flat tokens, zero claymorphism.** Clay treatment applies only to: buttons, header, dialogs, code-block container, editor field. Verify desktop replicates this exact scoping — do not apply clay/soft-shadow styling to body text.
- [ ] Style = soft/diffuse (not "inflated pastel"): diffuse shadow below-right, light inner rim above-left, shallow vertical tint gradient across the fill.
- [ ] RestElevation = 6dp · PressedElevation = 1dp (pressed controls **flatten**, don't invert — matches a CSS `:active`).
- [ ] `ClayInsets`: independent h/v control (default 1.5dp/1.5dp) so a wide-short control doesn't get a disproportionately thick stroke on its long axis.
- [ ] **Raised** treatment: shadow alpha 0.55 dark/0.16 light; fill = vertical gradient, lightened top (+0.05 dark/+0.035 light) → base → darkened bottom (−0.04 dark/−0.03 light); inner rim-light stroke via diagonal linear gradient, white alpha 0.85 light/0.06 dark at top-left fading to black alpha 0.05 light/0.18 dark at bottom-right, stroke width = min(insetH, insetV). When pressed: rim-light **skipped entirely**, only flattened shadow remains.
- [ ] **Pot** treatment (tables, drawer Recent panel): raised outer lip (same as above) PLUS an inner sunken basin — flat alpha 0.30 dark/0.10 light, inset = 4× the base inset, skipped if the control is too small to hold both bands legibly.
- [ ] **Inset** treatment (editor textarea, search fields): flat background + top-down black gradient (alpha 0.28 dark/0.07 light, fading to transparent by 18% of height).
- [ ] Exactly **3 radius steps** used by all clay treatments: sm=4dp, md=8dp, lg=12dp — no fourth value.

### Typography

- [ ] Three typefaces, strict separation — never cross-use:
  - Body/reading: **Source Serif 4** (400, 600)
  - UI chrome: **Inter** (400, 600)
  - Code/mono: **JetBrains Mono** (400, 700)
- [ ] Headings always body-serif weight 600 — never a display face, never Inter.
- [ ] Button/header labels never in body serif — always Inter.
- [ ] Type scale (resolved against an **18px root, not 16px** — explicit "looks close but feels wrong" trap, verify desktop's root matches its own intended value):
  - body 18sp / 1.4 line-height
  - inline code 15sp
  - code block 12sp
  - h1 36sp (2rem) / 1.2 · h2 28.8sp (1.6rem) / 1.25 · h3 24.3sp (1.35rem) / 1.3 · h4 20.7sp (1.15rem) / 1.35 · h5 18sp (1rem) / 1.4 · h6 16.2sp (0.9rem) / 1.4
  - button 15.75sp (0.875rem) · button-compact 13.5sp (0.75rem)
  - small/alert text 14.6sp (0.8125rem)
- [ ] Text-size stepper multipliers: 0.875× / 1.0× / 1.15× / 1.3× — applies to body/headings only.
- [ ] Inline-code pill/reference text = 0.85× body.
- [ ] Reading column max-width (`Measure`) = 48rem = **864dp** at the 18px root, centered, applied to both header content and body column.

### Spacing scale (11 steps, resolved against 18px root)

s1=0.25rem/4.5dp · s2=0.5rem/9dp · s3=0.75rem/13.5dp · s4=1rem/18dp · s5=1.25rem/22.5dp · s6=1.5rem/27dp · s7=2rem/36dp · s8=2.5rem/45dp · s9=3rem/54dp · s10=4rem/72dp · s11=5rem/90dp · s12=6rem/108dp

- [ ] Radius scale exactly 3 steps: sm=4dp, md=8dp, lg=12dp (same as claymorphism section — one shared scale, not two).

### Brand mark / logo

- [ ] Rounded-square tile, ~18.75% corner radius (96-unit radius on a 512 viewport), linear vertical gradient fill top `#DD8562` → bottom `#C8542D` (verify exact top-stop hex against the canonical brand SVG — it's close to but not identical to the named `Clay.c400 = #E29981` token; don't silently substitute one for the other without checking the source SVG).
- [ ] Cream "C" cutout, fill `#FAF9F5` (same value as the light-theme surface token), rendered as a ring/arc segment, not a literal glyph outline.
- [ ] Wordmark rendered as **live text** (Inter SemiBold, lowercase "claymark"), letter-spacing exactly `-0.0125em` (reproducing the source SVG's `-2` tracking at `font-size=160`) — not a rasterized/traced SVG, so it scales cleanly at any size. Verify desktop's wordmark rendering matches this letter-spacing value.
- [ ] Logo+wordmark lockup used in the drawer at 26dp mark size.

## 7. Other Interactive Behaviors (desktop analogs noted)

- [ ] **Share/paste-in handling**: Android accepts raw text/markdown via the OS Share sheet as a synthetic non-writable document (Save routes through Save-as). Desktop analog: drag-and-drop of text/markdown onto the app window, and/or "paste from clipboard as new document."
- [ ] **File-association / "open with" handling**: registered for markdown mime types and `.md`/`.markdown` file extensions; opens directly, bypassing the welcome screen; opens read-only (transient grant). Desktop: register Tauri as the OS file handler for `.md`/`.markdown` (double-click, right-click "Open with"), and support drag-a-file-onto-the-dock/taskbar-icon.
- [ ] **Flush-on-background**: crash-recovery draft force-flushed (no debounce) when the app is about to be killed/backgrounded. Desktop: flush synchronously on window blur, app suspend, and app-quit — must complete before the process can actually exit.
- [ ] **Dynamic shortcuts** (up to 3 most-recent docs as OS launcher long-press shortcuts): optional desktop analog = Windows jump list / macOS Dock menu via Tauri's native menu APIs. Low priority, explicitly optional.

## 8. Explicitly NOT required — do not build these to "catch up" to Android

- [ ] **Print/Print-to-PDF** — Android doesn't have a working one either (archived after the old implementation rendered raw source through a monospace layout, not the actual styled document, and looked broken). Not a parity requirement.
- [ ] **34-language hand-rolled lexical syntax highlighter** — an Android-only JVM workaround for lacking a TextMate engine. Desktop should keep its existing full Shiki-based highlighting; do not regress to this subset or its two fixed palettes.
- [ ] **No remote image fetching** — Android has no network permission at all, so images always fall back to alt-text. This is flagged in the Android project's own docs as *inconsistent* with the web build's URL policy (which does allow http/https image `src`). **This is an open product decision, not a settled requirement** — keep desktop's existing network-capable image behavior unless the team explicitly decides otherwise.
- [ ] **Mixed-content inline math** (bold/link/code combined with `$…$` in one paragraph) not supported on Android — only pure-text paragraphs route to KaTeX there. Desktop's presumably richer web-based math pipeline should not be downgraded to match.
- [ ] **No streaming/incremental rendering** on Android (single local file, no streaming source) — but streaming markdown IS a real feature of the web/Tauri build (mentioned in the native port's own docs as something the web app has that Android intentionally doesn't need). Preserve it on desktop; this is not something to remove.
- [ ] **Long-press-triggered tooltips** — an Android touch-input necessity. Desktop should use standard hover-triggered tooltips instead, not literally port long-press.
- [ ] **Home-screen widget** — no direct Tauri/desktop equivalent (OS home-screen concept doesn't exist on desktop). Out of scope unless the team wants a tray-icon "quick open recent" as a loose analog — not a requirement.
- [ ] **AMOLED toggle's original rationale (OLED power saving)** doesn't apply on desktop hardware — if a pure-black theme variant is kept, it's a pure design choice at that point, not a power feature; naming/framing in Settings should probably change accordingly rather than being ported as "AMOLED."

## Cross-check reminder

Before treating any single item above as a real desktop gap: check the
existing `src/` web app / `desktop/` code first. Given the ledger and
progress notes on this repo, the web build is generally **more** feature-rich
than Android in several areas (full Shiki highlighting, richer math,
streaming rendering — see §8), and Android is the newer, sometimes-simplified
port. Don't assume Android is the reference implementation across the board —
it's the reference for **UI chrome, theming, and document-management UX**,
which is where this checklist is most likely to surface genuine desktop gaps
(e.g. the responsive drawer breakpoint, the claymorphism system's exact
values, the keyboard shortcuts, the file-association/drag-drop behaviors).
